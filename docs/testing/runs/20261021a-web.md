### Automation notes for this lane

- **Semantics placeholder.** The deployed build has no `AUTOMATION` define, so the helper must click `flt-semantics-placeholder`. The engine removes that placeholder on the first pointer event that is not aimed at it, so on a reload with the pointer over the pane it can vanish before `enable()` runs, and semantics then stay off until the next load. Calling `enable()` in a 25 ms poll straight after `navigate`, in the same `browser_batch`, always caught it.
- **Frames.** The pane renders no new frame while it is idle, so the semantics tree can lag behind the screen. A `computer` screenshot flushes it, as the Chrome extension does.
- **Clipboard.** The pane refuses `navigator.clipboard.writeText` from synthetic taps (`Write permission denied`) and refuses `readText`. The app still shows its `… copied to clipboard` toast. Copied values were read by wrapping `writeText` in the page, which records the text the app passes in. Clipboard-dependent checks (paste into a field) need a real click.
- **Toasts.** With semantics on, Flutter's `accessibleNavigation` is true, and a SnackBar that has an action (`Dismiss`) then never times out. Toasts queue and stay until dismissed, so the lane dismisses them between steps. This is a side effect of the automation mode, not a product defect.
- **Side nav and `Select Account`.** The side-nav buttons (and `Collapse navigation`) appear in the semantics tree only some of the time; it is not true that they are always absent, as S1 first assumed. `Select Account` never has a button node. Both are tapped with synthetic pointer events at viewport coordinates when no node is present (1280×900 viewport: nav x 96, `Select Account` 101,101). The `Addresses` panel opens on a synthetic `pointermove` over the bottom-left tab, and its row menus are the unlabelled buttons in each row.
- **Hidden pane.** From S3 the browser pane was hidden in the app most of the time. Flutter then rendered no frames, so scripted taps acted on a stale screen, and once a stale semantics rect sent a tap to a transaction card. A small in-page shim makes `requestAnimationFrame` fall back to a 40 ms timer when the browser does not call it. With the shim the app renders normally while hidden; it is an automation aid only.
- **Viewport.** S3 ran with the pane's viewport emulated at 1280×900 (`resize_window`). That stopped screenshots drawing the app at about 40% scale in the corner, which S1's 1024×768 dashboard screenshots do.
- **Notifications.** Transaction notifications remove themselves after 5 s (`TransactionNotificationProvider.add`). A 500 ms in-page sampler logs every notification label, so none are missed between polls; it ran from TC-TOKEN-009's auto-mint onwards.
- **Files.** The pane has no file-upload tool. Token icons use the served `assets/images/icon.png` (byte-identical to the repo file); NFT assets `sc-a/b/c.png` are 256×256 PNGs drawn in the page (red `A`, green `B`, blue `C`, about 3.6 KB). Both are handed to the app by wrapping `HTMLInputElement.prototype.click` for file inputs, as in 20260927a.
- **Two parties.** TC-DASH-005 used a second pane tab on the same origin, unlocked as another stored account; each tab keeps its own in-memory session.
- **Screenshots.** Coordinates come from semantics rects or from 1280×900 screenshots (×1.6), never from the scaled S1 screenshots.

## Failures

### TC-ADNR-006, TC-ADNR-015, TC-ADNR-016 · Domain notifications never fire (#304)
- **Actual:** create, transfer and delete all work, but no `Domain Name Created`/`Transferred`/`Deleted` notification appears.
- **Cause:** `TransactionSignalProvider._handleAdnr` compares `Function` against `AdnrCreate`, `AdnrTransfer`, `AdnrDelete` (and the BTC variants) without `()`; the chain data and the rest of the GUI use `AdnrCreate()`. The handler is shared, so desktop is very likely affected too.

### TC-TOKEN-021 · The `Pending Pause` spinner swallows taps (#307)
- **Actual:** tapping `Pending Pause` shows no `Token state change is pending. Please wait` toast. Nothing is sent, which is correct.
- **Cause:** `AppButton(processing: true)` replaces `onPressed` with a no-op (buttons.dart:435-449), so the toast handler in web_token_management_actions.dart:257-266 (and pause_token_button.dart on desktop) is unreachable.

### TC-TOKEN-024 · New voting topics do not appear until a page reload (#308)
- **Actual:** two topics created and confirmed (Spyglass lists both), but the `Voting` sheet showed none for 4 minutes and across re-entries; it made no request when reopened. After a full reload both appear.
- **Cause:** `webTokenTopicListProvider` is a non-autoDispose family that calls `load(1)` once and is never invalidated.

### TC-TOKEN-025, TC-TOKEN-026 · Vote percentages shown 100× too small (#309)
- **Actual:** `Votes Yes 1%` after one Yes vote (expected 100%); `0.5%` / `0.5%` after one Yes and one No (expected 50% each). The counts are right.
- **Cause:** Spyglass returns `percent_yes`/`percent_no` as fractions; `WebTokenVoteTopic.toNative()` copies them unchanged into `percentVotesYes`/`percentVotesNo`.

### TC-TOKEN-031 · The previous owner's balance disappears after an ownership change (#310)
- **Actual:** after `TokenContractOwnerChange()` (block 1178050), T2 vanishes from A's list. Spyglass holders read `{B: 0.0}` with supply 500, and A's `/tokens/` omits T2. Expected: A keeps its 500.
- **Unknown:** whether Core agrees (Spyglass bug) or moved/zeroed the balance (consensus bug). The macOS lane's TC-TOKEN-031 reads Core directly.

### TC-SC-023 · Stale evolve property, and missing evolve date (#311, #312)
- **#311:** the new contract's evolve stage 1 opened with `Mood: Happy` from TC-SC-022's stage 1. `EvolvePhaseFormProvider.clear()` does not reset `properties`. Removed by hand before saving.
- **#312:** `Reveal Evolve Stages` shows no `Evolve Date:` for the date stage. `WebNft` reads `EvolveDate` only when it is a number; the chain data holds the ISO string `2026-10-22T04:00:00Z`.

### TC-DASH-002 · Dashboard Latest TX shows outgoing sends in green (#315)
- **Actual:** an outgoing `20 VFX` (A → run account) reads green on the VFX card; the Transactions list shows it red.
- **Cause:** `_LatestVfxTx` (web_dashboard_container.dart:1097-1105) colours red only when `amount < 0`; web transaction amounts are positive.

### TC-SEND-012, TC-SEND-027 · Send links never prefill (#317)
- **Actual:** after unlocking on `#dashboard/send/vfx/<B>/2.5` the Send form opens empty; opened in the running session, the route shows a blank page (app bar and back arrow only), and that blank route then sticks to the Send tab until Back clears it. Failed the same way in 20260927a, although the deployed build includes 92597634 and 177153df.

### TC-SEND-016 · Mainnet address gets `Invalid Address.` instead of the other-network message (#306)
- **Cause:** `formValidatorRbxAddress` rejects the wrong first letter before `isOtherNetworksVfxAddress` runs, so that branch is unreachable for real addresses. Filed by the macOS lane as #306 with the web evidence added; #316 is a duplicate the web lane filed by mistake (labelled `duplicate`, left open for a maintainer to close).

### TC-TOKEN-017 · Doubled apostrophes in UI strings (#318)
- **Actual:** `This address''s (<A>) 20261021AW1 balance is insufficient.` Nine English ARB strings use `''` while l10n.yaml lacks `use-escaping: true`, so the quotes render literally (also `What''s this payment for?`, `This token doesn''t have any voting topics yet.`, and others).

### TC-TOKEN-033 · T2 missing after the ownership change (#310)

### TC-SC-025 · NFT search Clear keeps the filtered list (#319)
- **Actual:** Clear empties the field but the list keeps the last results (one NFT, or `No NFTs found.`) until Refresh. **Cause:** the web Clear handler calls `load(1)` without the session addresses that Search and Refresh pass (nft_navigator.dart).

### TC-BTC-011 · On testnet every BTC send pays 5 sat/vB (#327)
- **Actual:** `Half Hour` (8 SATS) picked and shown in `Please Confirm`, but eabc5c5d… paid 700 sats for 140 vB (5.0 sat/vB), the same as every Economy send.
- **Cause:** `assets/js/btc.js` `createTransaction` sets `feeRate = 5` on testnet after applying the caller's rate. Mainnet is not affected.

### TC-SEND-010, TC-BTC-011 · The BTC balance ignores unconfirmed transactions (#328)
- **Actual:** after four sends the header, send form and Fund sheet still read `0.00050000 BTC`; mempool.space shows 15,200 spendable sats.
- **Cause:** `btc.js` `addressInfo` uses `chain_stats` only; the 2-second `refreshBtcBalanceInfo` re-reads the same confirmed-only figure.

### TC-BTC-017 · Deposits into an owned vBTC contract are not marked vBTC (#329)
