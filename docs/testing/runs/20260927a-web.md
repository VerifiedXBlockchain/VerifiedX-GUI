### TC-SEND-020 · Send form validates against a stale balance after a send confirms

That value is only set on login, account switch and currency-segment change (lib/core/providers/web_session_provider.dart:257 and :311, lib/features/web/providers/web_currency_segmented_button_provider.dart:27-47); the 30 s `loop()` (web_session_provider.dart:346-376) refreshes `session.balance` but never the selected account. ### TC-VAULT-029 · After a recovery, the web Vault screen does not show the deactivated state (760f16fd)
- **Steps:** Run web account (Account 3), Vault W activated with 9.99997 VFX available and a 1 VFX timelocked send to B outstanding. Recover > Proceed (confirmed on chain within ~1 min). Reloaded `?automation=1`, unlocked Account 3 with TEST_ENCRYPTION_PASSWORD, opened Vault Account and waited 20 s.
- **Expected:** `Warning` / `This vault account has been recovered and therefore deactivated.` / `Please create a new web wallet account if you'd like to use this feature.`
- **Actual:** the normal screen for an unused vault: `Warning` `Your vault account is not activated yet. To protect funds and assets securely, please activate first.`, `Available Balance: 0 VFX`, `Status: Awaiting Funds` with `Fund Account`, and an enabled `Recover` button. Spyglass for the vault at the same time: `{"balance":"0.0000000000000000","balance_total":"0.0000000000000000","balance_locked":0.0,"activated":true,"deactivated":true}`. Everything else about the recovery was correct (see the row).
- **Screenshots:** shots2/TC-VAULT-029-in-progress.jpg (before reload), shots2/TC-VAULT-029-FAIL-after-reload.jpg
- **Cause (app bug, probable):** after recovery Spyglass returns `balance` and `balance_total` as JSON **strings** (`"0.0000000000000000"`) instead of numbers. `WebAddress.fromJson` casts `(json['balance'] as num)` (lib/features/web/models/web_address.g.dart:12), which throws, and `ExplorerService.getWebAddress` (lib/core/services/explorer_service.dart:76-83) swallows the error and returns `WebAddress(address, balance: 0.0)` with `deactivated: false`, `activated: false`. `getRaAddress` (lib/core/providers/web_session_provider.dart:404-418) then stores `raDeactivated: false`, so the check at lib/features/reserve/screens/web_reserve_account_overview_screen.dart:110 never fires. The same silent fallback also makes a recovered vault look `Awaiting Funds` and re-offers `Fund Account`/`Recover`, so a user could send funds to a dead vault. Fix: parse numeric strings (`num.tryParse`/a `JsonConverter`) and do not swallow parse errors into a default object; the Spyglass serializer should also return numbers.

## Other findings (part 3, not case failures)

- **Wizard progress dialog stuck after a mint error:** in TC-SC-054 the loop returns on the first failure (sc_wizard_provider.dart:789-793) without closing the dialog or setting progress, and `Close` is enabled only at `percent >= 1` (sc_wizard_minting_progress_dialog.dart:66), so the dialog shows `Minting 1/3... 0%` with a disabled Close. Escape (barrier) does dismiss it. Minor app bug.
- **CSV import silently ignores LF line endings:** `CsvToListConverter()` (sc_wizard_provider.dart:435) defaults to `\r\n`; an LF-only file parses as one row, passes the header check (the header string is contained in the merged row) and imports zero rows with no toast. The bundled example CSV is CRLF. Users on macOS/Linux editors will hit this. Fix: `CsvToListConverter(eol: '\n')` after normalizing `\r\n`, and show a toast when no rows are imported.
- **Error dialogs where cases expect toasts:** `Asset is required` (TC-SC-018) and `Time must be in the future.` (TC-SC-019) open an `Error` dialog with Close.
- **Confirm-dialog buttons:** feature/stage/instance delete dialogs use `No` / `Delete`, not `Cancel`.
- **Percent formatting:** royalty cards and wizard subtitles print `5%` / `7.5%`, cases expect `5.0%` / `7.5%`.
- **Add Another Feature hidden under the bottom bar:** with two feature cards at a 1029 px viewport the button sits under the Compile & Mint bar and cannot be clicked with the pointer (DOM click works; scrolling the creator did not move it).
- **Butterfly login URL** puts the encrypted key in the URL fragment (`/login/key#…`, 366 chars), so it is not sent to the server in the request line; still appears in browser history.
- **Faucet close re-opens the domain dialog:** after closing the VFX Faucet from the BTC-domain flow, `New BTC Domain` appears again (TC-MISC-031; also seen in part 2 TC-ADNR-019).
