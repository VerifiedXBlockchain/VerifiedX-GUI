## Questions

- **Release after the signers broadcast (TC-BTC-064 attempt 1).** When a part's original payout is already in the mempool, a release (or raise) at the minimum next rate races it: here the regular block mined the original 2 min after the release was mined on VFX, and Core settled the part as paid (correct). Should the dialog say that a release can lose to a payout already broadcast, or should the minimum release rate be high enough to replace it (BIP 125 needs the new fee to exceed the old fee plus the relay fee of the new size)?
- **`Minimum` is 2 sat/vB** in the fee picker on this build while the signet quotes 1, so the case's "`Minimum` (1 sat/vB on the signet)" was run as `Custom` 1.
