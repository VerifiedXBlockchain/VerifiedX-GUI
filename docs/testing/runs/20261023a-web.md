## Failures

### TC-BTC-017, TC-DASH-003 · Incoming BTC shows the sender's change in the amount (#347)

`BtcWebTransaction.amount()` drops only outputs paid back to an input's address. The signer wallet sends change to a fresh address, so the 0.002 BTC funding shows as `1.49799436 BTC` on the BTC tab and the dashboard card. Details and balances are right. Filed #347 (P1).

### TC-SEND-013 · A BTC send link opens the VFX form after an unlock (#317)

The link's address and amount now reach the form, but its `btc` currency does not survive the unlock: `Send VFX`, VFX selected. In a running session the same link is correct. Commented on #317 (open), which had the empty form and blank page on 8.0.6.

### Not a case failure · The fee picker shows the fallback rates (#348)

The picker's 6 / 12 / 25 / 27 / 30 sat/vB are `BtcRecommendedFees.fallback()`. `https://signet.verifiedx.io/api/v1/fees/recommended` answers `1` for every tier, but its response carries `Access-Control-Allow-Origin: *` twice, so the browser rejects it (`Failed to fetch` from the wallet page; `/api/blocks/tip/height` fetches fine) and the wallet falls back silently. Server-side fix; filed #348 (P2). TC-BTC-011 and TC-SEND-010 pass because the send pays the rate shown.

### TC-BTC-027 · A vBTC token's Transactions list never refreshes (#351)

The detail screen keeps the deposit address's transaction list from its first visit (a non-autoDispose family provider that loads once), and its 10 s refresh reloads only the token. A deposit made from that screen stays hidden until a page reload. Filed #351 (P2).

### TC-BTC-025 · The wizard's View Token lands on the list (#349)

`View Token` pops the wizard with the token, and the caller (`tokenized_btc_list_screen.dart` line 211) ignores the result. Filed #349 (P2). Everything else in the wizard passes on 9.0.0 (#331 commented).

### Not a case failure · Spyglass says no vault is watched (#352)

`is_watched: false` on all three contracts, though their deposits were credited through a Bitcoin Report. The GUI does not read the flag. Filed #352 (P2, component:spyglass).

### TC-BTC-040 · Bulk transfer strips the underscore from a zfx_ recipient (#345)

Unchanged from 20261021a: the bulk recipient field turns `zfx_…` into `zfx…`, so the privacy message never shows (`Invalid Address.` instead). The single-token sheet handles the same input. Commented on #345.

### TC-BTC-044, TC-BTC-053, TC-BTC-055, TC-BTC-056, TC-BTC-057 · Spyglass loses track of watched withdrawals (#354)

Spyglass keeps every watched-vault request at `requested` (a cancelled one at `cancellation_requested`), with no pin state, and its per-address balances go wrong once withdrawals settle: B's paid 0.00002 came off A's balance, a release refund is not shown, a cancelled request still zeroes C's available balance. The web wallet reads those balances for `My Balance`, and it treats a `requested` row as live for 360 blocks, so `Withdraw` keeps reopening a finished withdrawal for about an hour. Filed #354 (P1, component:spyglass), with a second comment on the balances.

### TC-BTC-053 · The history row still offers resume and cancel on a watched vault (#346)

Unchanged from 20261021a, now also after the withdrawal completed. Commented on #346.

### TC-BTC-055 · Releases listed twice (#355)

Each `vBTC Withdrawal Release` appears twice in the VFX list, though Spyglass returns it once. Filed #355 (P2).

## Questions

- **Token Created without a contract id (TC-BTC-023).** The web ceremony's `Token Created` dialog has no `Smart Contract ID:` row on 9.0.0; it appears only when the create response carries `SmartContractUID`. Is the id meant to be shown there (the case expects it)?
- **Fee estimate for Taproot outputs.** The vault deposits picked 12 sat/vB and paid 1,680 sats for 152.75 vB, 11.0 sat/vB: the web fee looks computed for a 140 vB P2WPKH transaction. Close enough to the picked rate; noting it in case the estimate should use the real size.
- **Two minimum-payout rules (TC-BTC-044, 053).** The request check said `the payout must be at least 330 sats` (`…minimum at this fee rate is 0.00002178 BTC`), and the verification of a 1,000-sat withdrawal at 3 sat/vB said `leaves less than 546 sats to pay`. Which floor is meant (330 for P2WPKH, or 546 for every output)?
- **Waiting for Confirmation text on a watched vault.** It still reads `FROST signing will begin automatically once confirmed.`, though no FROST step follows. Change it for watched vaults?
- **Second-account view (TC-BTC-058).** A holder's detail lists only its own withdrawals in `Withdrawal History:`, so another account's open withdrawal can't be opened there and the case's guard text never shows. Is the case outdated, or should other requesters' rows show?

The chain handles it (the payout is paid), but the user's raise or release then does nothing. Worth a note in the dialog?
- **Detail page after an account switch.** With A's web2 detail open, switching to C left the page on A's token with its owner buttons (`Fund`, `Withdraw`, `Transfer Ownership`, …) until Back. Should a switch leave owner-only pages?
