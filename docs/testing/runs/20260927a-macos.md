### TC-DASH-030 · Status panel has no CLI Version row (GUI attached to a running CLI) — real app bug, P1

- **Steps:** GUI started while a CLI was already listening on 17292 (the attach path); Operations → Status.
- **Expected:** `CLI Version` row with the same value as the boot log line `CLI Version: <version>`.
- **Actual:** no `CLI Version` row, and no `CLI Version:` line in the Activity Log. The CLI answers `GET /api/V1/GetCLIVersion` with `8.0.0.1730-beta`.
- **Screenshot:** `TC-DASH-030.png`.
- **Cause (read-only):** `lib/core/providers/session_provider.dart:879-891`: when `_cliIsActive()` is true, `_startCli` sets the token, fetches config, logs `CLI is already running!` and returns, skipping `_cliCheck` (lines 839-857), which is the only place that calls `getCliVersion()` and sets `state.cliVersion`. The Status row is gated on `cliVersion != null` (`lib/features/operations/screens/operations_screen.dart:208`). The attach branch skips `passwordRequiredProvider.check()` / `walletIsEncryptedProvider.check()` as well (they only ran from other call sites, first with an empty token, giving the two 403 `BridgeService.checkIfEncrypted` traces at the top of the log). Fix: fetch the CLI version (and run the two checks) in the attach branch too.
- **Env note:** only visible because this run attached to a pre-started CLI; the same happens to any user whose GUI restarts while its CLI keeps running.

### TC-AUTH-006 · Manual Import Snapshot always fails on testnet — real app bug, P2

- **Steps:** Operations → General → `Import Snapshot` with local height 1014063.
- **Expected:** toast `Your local blockheight is further along than the snapshot.`
- **Actual:** red toast `Problem fetching snapshot block height. Please try again.`
- **Screenshot:** `TC-AUTH-006.png` (toast captured by `wait-for-text`).
- **Log:** `flutter: CHECK REMOTE INFO` then `flutter: type 'Null' is not a subtype of type 'String' in type cast` (lines 59-60 and 308-309), followed each time by `Unhandled Exception: PathNotFoundException: Cannot create file, path = '…/vfx-gui-automation/rbxtest/Databases/debug-gui.txt'` (8 times in the log).
- **Cause (read-only):** `https://data-testnet.verifiedx.io/api/applications/` returns `"snapshot":{"height":212050,"url":null,…}`, but `RemoteInfoSnapshot.url` is `required String` (`lib/features/remote_info/models/remote_info.dart:84`), so `RemoteInfo.fromJson` throws and `RemoteInfoService.fetchInfo()` returns null (`lib/features/remote_info/services/remote_info_service.dart:25-31`). `import_snapshot_button.dart` then shows the snapshot-height error. Side effects: the GUI update check (`session_provider.dart:checkRemoteInfo`) can never fire on testnet, and the button compares against this stale `/applications/` snapshot height rather than `SnapshotService().fetchLatest()` (1007847), which the startup prompt uses. Secondary bug: `DebugLogger.log` writes to `<dbPath>/Databases/debug-gui.txt` (`lib/features/debug/debug_logger.dart:7`), but on testnet the folder is `DatabasesTestNet`, so every logged error raises a second unhandled exception. Server-side, the `/applications/` data (GUI 4.0.3, CLI 4.0.1 from 2023) is also stale.

### TC-DASH-023 · Balance cards stay collapsed after leaving All My Tokens through the side nav — real app bug, P2

- **Steps:** Dashboard → `Tokens` → `All My Tokens` → side-nav `Dashboard` (`tap-key nav:dashboard`).
- **Expected:** back at the dashboard root with the VFX/BTC balance cards expanded (as after `Back`, TC-DASH-009).
- **Actual:** the root shows, but the balance cards stay collapsed (headings only, empty area above the price cards) until another tab is opened and Dashboard is chosen again.
- **Screenshot:** `TC-DASH-023-repro.png`, `TC-DASH-025-after.png`.
- **Cause (read-only):** only the All My Tokens back button calls `globalBalancesExpandedProvider.expand()` (`lib/features/home/screens/all_tokens_screen.dart:110`). The side-nav Dashboard item on the already-active tab does `popUntilRoot()` (`lib/features/navigation/components/root_container_side_nav_list.dart:54-57`); the tab listener that re-expands (`lib/features/navigation/root_container.dart:142-153`) only reacts to tab changes. That listener is also added inside `build` on every rebuild and closes over a stale `globalBalancesExpanded`.

### TC-SEND-028 · QR dialog's Save button renders at the screen edge — real app bug, P2

## Part 2 failures

### TC-VAULT-005 · Auto-activation never fires after funding a new Vault — real app bug, P0

- **Steps:** Vault Accounts → `Setup New Account` (Vault D xRBX3FSuN8i8115Y2gtzFtGnrCLeag6q1N) → `Fund Account` → `Send` → `Please Confirm` `Send` → `Funds Sent` `Close` → `Auto Activate?` `Yes` → password → `Submit` (about 20 s of dialogs in total).
- **Expected:** once the 5 VFX land, toast `Vault Account Auto Activation process initiated`, then `Activated` within 2 minutes.
- **Actual:** `Auto activate queued.` and badge `Activation Pending`; the 5 VFX confirmed at once (Spyglass balance 5.0) but no activation was ever sent (`activated: false` 2 h later, no publish call in the log). The card stays `Activation Pending` with no `Activate Now` button, and the Manage screen hides `Activate\nAccount` too, so the Vault cannot be activated until the app restarts.
- **Screenshots:** `TC-VAULT-005-confirm.png`, `TC-VAULT-005-pending.png`.
- **Log:** `flutter: {address: xRBX3FSuN8i8115Y2gtzFtGnrCLeag6q1N, password: <REDACTED>}` (the provider prints the Vault password in clear, see Observations); no `ReserveAccountService.publish` afterwards.
- **Cause (read-only, likely):** `ReserveAccountProvider.fundAccount` registers the funding hash only after the `Funds Sent` info dialog, the `Auto Activate?` confirm and the password prompt (`lib/features/reserve/providers/reserve_account_provider.dart:142-176`). Meanwhile the 10 s main loop reloads the Success list and `TransactionSignalProvider.insert` handles the funding transaction as soon as it confirms (`lib/features/transactions/providers/transaction_signal_provider.dart:56-66`, `_handleFundsTransfer` `:138-161`). If the transaction confirms before the user finishes the dialogs (testnet blocks every ~12 s), it is handled with no auto-activate entry and then deduplicated by hash forever, so the queued entry is never used. Also `pendingActivationProvider` (`pending_activation_provider.dart`) never clears an id, which is why the manual `Activate Now` stays hidden (`reserve_account_overview_screen.dart:222`, `manage_reserve_accounts_screen.dart:112`). Fix: register the hash right after broadcast (before the dialogs), or check the balance/transaction when the entry is added; and clear or expire pending ids.
