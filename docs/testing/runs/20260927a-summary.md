## Spyglass testnet outage (backend, not fixed; needs Tyler)
- POST https://data-testnet.verifiedx.io/api/raw/smart-contract-data/ returns 500: `ValueError: q must be exactly 160, 224, or 256 bits long` from paramiko `dsskey.sign_ssh_data` during SSH auth to the compile host. Blocks every web token and smart-contract/NFT mint.
- Code: vfx-explorer (branch testnet) connects with `paramiko.SSHClient().connect(host, username=RBX_SHOP_WALLET_USERNAME, password="", key_filename=RBX_WALLET_SSH_KEY_PATH)` (shop/media.py ~164-172, same pattern at ~211 and ~249); paramiko==2.11.0. With look_for_keys/allow_agent left at their defaults, paramiko also tries any DSA key it finds (agent or ~/.ssh), and newer `cryptography` rejects 1024-bit DSA signing with exactly this error.
- Likely fix: pass `look_for_keys=False, allow_agent=False` (and ideally an explicit `pkey=` of the real key type), or remove the stray DSA key on the server; check the key at RBX_WALLET_SSH_KEY_PATH is RSA/Ed25519. Deploying needs Tyler.
